# AReA project page

`/area/` on this site. A plain static page (no build step, no framework) in the visual language of the AReA method
videos: navy ground with drifting token dust, IBM Plex Sans and Mono, glass cards, and colours that mean something
(blue = Phase I, global and coarse; orange = Phase II, local and fine; teal = Halo; yellow = Global-KV Bridge;
coral = the problem). The title at the top is the videos' own AReA title animation.

## Images: how they load

High-resolution images are never sent as-is, and the heavy files are kept apart from the page's own files:

| file | where | when the browser fetches it |
|---|---|---|
| a ~600 byte blurred placeholder | inlined in `static/data/images.js` | immediately; it holds the image's exact shape, so nothing jumps |
| `w800` … `w3200` in AVIF and WebP (+ one JPEG fallback) | `static/img/<id>/` | when the image is about to scroll into view; the browser picks the size for the screen |
| full resolution, progressive JPEG (only for masters wider than 3200 px) | `full/<id>.jpg` | never on page load: only when a viewer zooms in or uses the teaser's magnifier |
| `lens.jpg`, a small full-resolution crop (teaser only) | `static/img/teaser/` | on load: the magnifier is parked on it, so it is sharp before the full file arrives |

Masters up to 3200 px wide get no separate full-resolution file: zoom uses their largest display file.

The teaser is the only image requested while the title plays.

### Size limits to keep in mind

- GitHub refuses any file over 100 MB (the build script warns past 95 MB). Use JPEG/WebP masters if a PNG is bigger.
- A GitHub Pages site should stay under 1 GB in total, and this repository already holds the SEGA and TPG pages.
  A full-resolution 8K × 8K JPEG is roughly 15 to 30 MB, so budget the number of full-resolution images accordingly.
- Git LFS is not an option: GitHub Pages serves LFS pointer files, not the images.

## Adding or replacing images

1. Put the full-resolution masters (PNG/JPEG/WebP/TIFF) in one folder **outside the repo**, or in `area/masters/`
   (git-ignored). The file name is the image id: lowercase, digits, `-` and `_` (e.g. `teaser.png`,
   `cmp-bottle-area.png`).
2. Build the derivatives (needs ImageMagick and ffmpeg):

   ```bash
   python3 area/tools/build_images.py path/to/masters            # only new or changed masters
   python3 area/tools/build_images.py path/to/masters --force    # everything
   python3 area/tools/build_images.py path/to/masters --prune    # also drop ids no longer in the folder
   python3 area/tools/build_images.py teaser.png --force --lens teaser=0.850,0.411   # teaser + its parked-lens crop
   ```

3. Reference the id in `index.html`:

   ```html
   <div class="frame" data-img="teaser" data-zoom data-sizes="(min-width: 1180px) 1152px, 100vw" data-alt="..."></div>
   ```

   - `data-zoom`: click to zoom, again for full detail, drag to pan, Esc or Reset to leave.
   - `data-magnifier` (the teaser): a lens parked at `data-lens="x,y"` (fractions) that follows the pointer;
     `data-lens-zoom` sets its power (4). Build its sharp parked crop with `--lens <id>=x,y` (below).
   - `data-full-link="none"`: no link to the full-resolution file under the figure (the page's figures use this).
   - `data-priority="high"`: load eagerly (only for the image at the top).
   - `data-sizes`: how wide the image is shown, so the browser picks the right file.
   - `data-ar="16 / 9"`: shape of the placeholder box shown while the id has no derivatives yet.

   An id that has not been built yet shows a labelled placeholder (`image · <id>`), so layout can come first.

### Comparisons

Side-by-side comparisons are listed in `static/data/results.js` (`AREA_COMPARISONS`): a label, model, resolution,
prompt and one image id per method. Panels of one comparison zoom and pan together. Build each method's master as
`cmp-<set>-<method>.png`.

## Previewing locally

```bash
# from the repo root
python3 -m http.server 8765
# open http://localhost:8765/area/
```

## Where the current images come from

- Figures from the paper live as SVGs in `assets/AReA/` (pipeline, teaser) and `assets/images/` (failures, comparison);
  the page never loads or links them.
- The teaser and pipeline masters were rendered from those SVGs in Chromium: the teaser at 5.65× (the density of the
  images embedded in it, 10,255 × 8,238), the pipeline at 4× with its Wingdings arrow replaced by a Unicode → (the
  SVG's arrow only renders where Wingdings is installed).
- The Figure 2 (failures) and Figure 5 (comparison) images are the 2048 px JPEGs embedded in those SVGs, extracted
  byte for byte.

## Notes

- The title animation is shared with the videos. To change it, edit `title.ts` in the video repo and rebuild
  `area-title.js` there (see that repo's README), then copy the bundle here.
- Text follows the paper's wording (see the videos' ALIGNMENT.md); numbers in `static/data/results.js` are the paper's.
- Reduced-motion users get the finished title, still dust and no autoplay.
